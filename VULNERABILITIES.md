# Уязвимости hackwebapp

## 1. SSTI → RCE

- **Где:** `app.py: dashboard()`, `current_user.bio` задаётся на `/profile`.
- **OWASP:** A03:2021 — Injection. **CWE:** CWE-1336 / CWE-94.
- **Причина:** `bio` прогоняется через `render_template_string()` —
  полноценный Jinja2-движок без песочницы. Любой `{{ ... }}` внутри
  исполняется как код с доступом к Python-объектам через
  `__class__`/`__globals__`.
- **Эксплуатация:** сохранить в bio
  `{{ cycler.__init__.__globals__.os.popen('id').read() }}`, открыть
  `/dashboard` — вывод команды появится в HTML.
  См. `exploits/exploit_1_ssti_rce.py` (проверено лично, работает).
- **Патч:** `bio` больше не проходит через `render_template_string()`,
  передаётся как обычная переменная — Jinja2 автоэкранирует вывод.
  `patches/01-ssti-rce.patch` (применён и проверен).

## 2. JWT `alg:none` forgery

- **Где:** `auth_jwt.py: jwt_decode()`, используется в `/api/login`,
  `/api/portfolio`, `/api/admin/users`.
- **OWASP:** A02:2021 / A07:2021. **CWE:** CWE-347.
- **Причина:** алгоритм верификации читается из заголовка токена
  (контролируется атакующим), `"none"` считается допустимым — токен
  без подписи с любым payload (включая `role: admin`) принимается.
- **Эксплуатация:** собрать токен `header={"alg":"none"}` +
  `payload={"role":"admin"}` без подписи, отправить на
  `/api/admin/users`. Никакой логин не нужен.
  См. `exploits/exploit_2_jwt_forgery.py` (проверено лично, работает).
- **Патч:** алгоритм верификации зафиксирован на сервере
  (`ALLOWED_ALG = "HS256"`), токен с любым другим `alg` отклоняется.
  `patches/02-jwt-alg-none.patch` (применён и проверен).

## 3. Stack Buffer Overflow → RCE уровня ОС

- **Где:** `native/ticker_validator.c: validate_ticker()`, дёргается
  из `/api/validate-ticker` через `subprocess`.
- **OWASP:** A05:2021. **CWE:** CWE-121, CWE-787.
- **Причина:** `strcpy()` копирует вход в 64-байтный стековый буфер
  без проверки длины. Бинарь собран без stack-canary и без PIE
  (`native/build.sh`), адрес возврата предсказуемо перезаписывается.
- **Эксплуатация (ret2win):** `72 × 'A'` + адрес функции
  `secret_backdoor()` (из `nm ticker_validator`) перезаписывает адрес
  возврата. При `return` из `validate_ticker()` управление уходит на
  `secret_backdoor()` вместо вызывающей функции — RCE на уровне ОС,
  не только внутри Flask-процесса.
  См. `exploits/exploit_3_buffer_overflow.py` (проверено лично,
  offset=72 и адрес `secret_backdoor` подтверждены на реальной сборке).
- **Патч:** `strcpy()` заменён на копирование с проверкой длины,
  вход длиннее буфера отклоняется; пересборка с
  `-fstack-protector-strong -pie` (defense-in-depth).
  `patches/03-buffer-overflow.patch` (применён и проверен).

## Дополнительные баги, найденные и исправленные при повторном аудите

Не часть трёх лабораторных уязвимостей, но ломали нормальную работу:

- **`models.py`: `DB_NAME = "database.db"`** — относительный путь,
  резолвился от текущей рабочей директории процесса на момент запуска
  `python app.py`, а не от папки проекта. Если сервер запущен не из
  корня (другой cwd в IDE/терминале) — файл базы создавался в другом
  месте, и любой код, ожидающий найти `database.db` рядом с проектом
  (включая `exploits/_lab_client.py`), не находил ни базы, ни
  пользователя в ней. Исправлено: путь теперь привязан к расположению
  `models.py` через `os.path.dirname(os.path.abspath(__file__))` —
  тот же паттерн, что уже использовался для `NATIVE_VALIDATOR` в
  `app.py`, просто не был применён последовательно.
- **`app.py: register()`** не проверял занятость `username` (только
  `email`) — регистрация с уже существующим именем падала с
  необработанным `sqlite3.IntegrityError` (500 вместо понятной ошибки
  пользователю). Добавлена проверка `get_user_by_username()` перед
  созданием аккаунта, по аналогии с уже существующей проверкой email.

## Что проверено лично (не просто "должно работать")

- Каждая из трёх уязвимостей воспроизведена напрямую на реальном коде
  проекта (SSTI — через Jinja2 `Environment`, JWT — через сам модуль
  `auth_jwt.py`, buffer overflow — через собранный `gcc` бинарник с
  реальным offset=72 и адресом `secret_backdoor`).
- Все три патча применены (`patch -p1`) к чистой копии проекта и
  реально закрывают уязвимость — повторная попытка эксплуатации после
  патча отклоняется сервером/бинарником.
- Весь Python-код (`app.py`, `models.py`, `forms.py`, `auth_jwt.py`,
  эксплойты) проходит `py_compile` без синтаксических ошибок, и каждый
  `url_for(...)` в шаблонах указывает на существующий маршрут в
  `app.py` (иначе — `BuildError`, как было раньше с `/profile`).
